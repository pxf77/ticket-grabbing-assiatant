# UX 设计说明

## 设计原则

购票开售是高压、短时、强时效场景。界面优先级应为：

1. 关键信息可读。
2. 行动按钮明确。
3. 通知授权不打扰。
4. 到点页极简。
5. 失败复盘结构化。

## 核心流程

```text
创建订阅规则 → 开启通知 → 进入倒计时页 → 开始待命 → 到点打开官方链接 → 手动购票 → 记录结果
```

## 通知授权

不要在首页首屏直接弹系统通知权限。应在用户创建第一条订阅规则后再提示：

- “开启通知”
- “安装 PWA”
- “添加兜底 Webhook”

这符合用户意图形成后的授权时机，降低拒绝率。

## 倒计时页

倒计时页只保留：

- 项目名。
- 场馆。
- 演出时间。
- 开售倒计时。
- 官方链接。
- 待命按钮。
- 手动购票 checklist。
- 成功/失败记录入口。

不要放复杂设置、统计图或长文说明。

## 待命模式

用户点击“开始待命”后，系统创建一次 `purchase_session`。到点时页面会尝试打开官方链接。浏览器可能拦截非即时用户手势触发的新窗口，因此页面始终保留“打开官方链接”按钮作为兜底。

## 失败复盘

失败原因应结构化：

- 忘记登录。
- 通知太晚。
- 页面打开慢。
- 官方链接错误。
- 预算不匹配。
- 实际售罄。
- 临时有事。
- 其他。

MVP 当前提供记录成功/失败入口，后续可扩展原因选择器和统计分析。
